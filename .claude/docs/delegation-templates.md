# 派工 Prompt 模板

> 用法：複製對應模板，填空 `{...}`，刪掉不適用的行，用 Agent tool 送出。每個模板已內建 model-dispatch.md 的三件套（目標與動機／驗收條件／回報格式）與回報合約。
> 通用鐵則：agent 是冷啟動的——它不知道你們剛聊了什麼。所有必要背景都要寫進 prompt；引用檔案給絕對路徑。

## T1. 搜尋／定位（subagent_type: `Explore`，不指定 model）

```
搜尋廣度：{quick|medium|very thorough}

目標：找出 {要找什麼：符號定義／某功能的所有觸點／某模式的出現位置}。
動機：{找到之後要拿來做什麼，讓它知道哪些鄰近資訊也值得回報}。

範圍：{backend/ 或 frontend/src/ 等，明確目錄}。排除 node_modules、.venv、dist、__pycache__、.backup。

回報格式：
- 每個發現一行：`檔案:行號 — 一句話說明`
- 最後一行：你認為的最佳切入點與理由（一句話）
- 不要貼大段程式碼。找不到就明說找不到＋你搜了哪些關鍵詞。
```

## T2. 實作（subagent_type: `general-purpose`，model: `sonnet`）

```
目標：{做什麼}。
動機：{為什麼做、給誰用，遇到取捨時往哪邊偏}。

背景（你是冷啟動的，先讀）：
- 先讀 D:/System_Of_Speeching/CLAUDE.md 的「硬規則」與「指令」段。
- 相關檔案：{絕對路徑清單}。
- 已知陷阱：{從 architecture.md 摘relevant的 1-3 條，例如雙身分系統／models.py 四層模式}。

要求：
- {具體行為要求，逐條}
- 遵循周邊程式碼的既有風格與慣例。
- 不改動任務範圍外的檔案。

驗收條件（你交付前自己先跑一遍）：
1. {測試指令，照 CLAUDE.md 抄} 通過。
2. {行為驗證：實跑什麼、預期看到什麼}。
3. 測試基線沒有新增失敗（backend 基線 6 failed / 2 passed，frontend 8/8 passed）。

回報格式：改了哪些檔（每檔一句話）＋驗收條件逐條的實際結果＋範圍外發現（一句話一條，不要處理）。上限 400 字。失敗就明說卡在哪，不要交半成品。
```

## T3. 重構（subagent_type: `general-purpose`，model: `sonnet`；批次機械套用改 model: `haiku`）

```
目標：把 {範圍} 的 {舊模式} 改成 {新模式}。
動機：{為什麼值得重構}。

模式定義（必須先在一處驗證過才發批次）：
- Before：{貼出舊模式的具體樣子}
- After：{貼出新模式的具體樣子}
- 邊界情況：{哪些長得像但不要動}

行為不變是硬約束：重構前後對外行為必須一致，不順手修 bug、不順手改風格。

驗收條件：
1. {測試指令} 通過，且與基線一致。
2. `grep {舊模式特徵}` 在範圍內零命中（或只剩明確列出的例外）。

回報格式：改動檔案清單＋grep 驗證的實際輸出＋任何你判定為邊界情況而跳過的位置（檔案:行號＋理由）。
```

## T4. 研究（subagent_type: `general-purpose`，model: `sonnet`；純 Claude Code 問題用 `claude-code-guide`）

```
問題：{要回答什麼，越具體越好，最好可判定真偽}。
動機：{答案會決定什麼行動}。

要求：
- 每個結論附出處（URL 或 檔案:行號）。查不到可靠依據的，明確標「查無依據」，禁止推測補位。
- 區分「官方文件說的」和「你推斷的」。
- 超過 30 行的整理寫到 {scratchpad 路徑}/research-{主題}.md，回傳路徑。

回報格式：逐題結論（各 ≤3 行）＋出處。上限 400 字。
```

## T5. 審查（優先用 `/code-review` skill；要 fresh-context 驗收用 subagent_type: `verifier`；品味裁決用 `arbiter`。清單裡沒有這兩個 agent 時走 model-dispatch.md §3 的 fallback）

verifier 派工：

```
產物位置：{檔案路徑清單或「當前工作樹的未 commit 改動」}。

驗收條件（逐條判定 PASS/FAIL）：
1. {可客觀檢查的條件}
2. {...}

注意：不要修改任何檔案。條件寫得無法客觀判定就回報「不可判定」。
（不要提供實作過程的敘述給它——只給條件和位置，避免污染判斷。）
```

arbiter 派工（多方案評審）：

```
裁決題：{一句話}。
候選方案：
- A：{方案＋支持理由}
- B：{方案＋支持理由}
背景檔案：{絕對路徑}。
要求：先驗證我給的前提是否屬實，再裁決。給一個明確選擇＋依據（≤3 條）＋這個選擇最可能錯在哪（1 條）。
```
