# PRD：上架批次管理與會員新品展示

> 狀態：**Draft**
>
> 版本：`v1.0`
>
> 文件類型：`Product Requirements Document`
>
> 關聯文件：[`docs/product-publishing-requirements.md`](./product-publishing-requirements.md)

## 1. 文件摘要

本 PRD 旨在定義「商品近況管理（上架作業）」功能的產品化重構方向，將其重新定位為 `上架批次管理`，並建立與會員系統串接的正式商品發布流程。

本次需求的核心不是單純改名，而是解決以下產品問題：

- 後台使用者以為完成「上架作業」後，會員端即可看到商品。
- 系統目前沒有真正的會員商品展示入口。
- 系統缺乏「建立上架批次」到「正式發布商品」之間的狀態與流程控制。

本 PRD 的最終成果，是讓系統形成一套清楚、可操作、可驗證的商品發布模型：

- 後台：建立與管理上架批次
- 會員前台：展示已發布的新品商品

## 2. 背景

目前系統已具備以下能力：

- 商品主檔管理
- 多 SKU / 款式管理
- 庫存數量管理
- 上架批次建立與結果清單匯出
- 會員中心的登入、訊息、點數與活動互動能力

但從產品角度來看，現況仍有明顯斷點：

1. 後台的「上架作業」只建立一筆批次紀錄，並未真正對會員發布。
2. 會員中心沒有商品展示頁。
3. 上架批次沒有發布狀態，因此無法區分「已建批次」與「已對會員可見」。
4. 使用者對於「商品上架後會顯示在哪裡」缺乏明確路徑。

因此，本專案需要把既有的內部作業頁，升級成一個完整的商品發布產品流程。

## 3. 問題陳述

### 3.1 使用者問題

後台使用者完成「上架作業」後，不知道商品實際會顯示在哪裡，也無法確認會員是否能看到。

會員端使用者目前也無法透過會員中心查看這些被稱為「上架完成」的商品。

### 3.2 產品問題

目前的「上架」一詞與系統實際能力不一致，導致：

- 名稱誤導
- 流程不完整
- 功能價值不清楚
- 前後台無法對齊

### 3.3 商業問題

若系統無法把後台整理出的商品有效發布到會員前台，則「上架」功能只能停留在內部作業層，無法形成真正的會員經營與商品曝光價值。

## 4. 產品目標

### 4.1 主要目標

- 明確重新定義後台「上架」功能的用途與邊界。
- 建立後台商品批次發布到會員前台的正式流程。
- 讓會員可在清楚的入口中找到已發布商品。
- 讓團隊能以「批次」為單位管理商品展示。

### 4.2 次要目標

- 提升後台使用者對商品發布流程的理解。
- 降低功能命名造成的誤解與教育成本。
- 為未來商品詳情、收藏、售完狀態、活動主題展示奠定基礎。

## 5. 非目標

本期 PRD 不包含以下範圍：

- 不串接外部電商平台 API
- 不建立完整購物車或結帳流程
- 不處理訂單轉購買閉環
- 不實作推薦演算法
- 不處理跨平台同步上架
- 不處理會員前台的商品搜尋與篩選高階能力

## 6. 成功指標

### 6.1 產品成功指標

- 100% 的「會員可見商品」皆來自 `published` 批次
- 後台使用者可在單一路徑內完成「建批次 -> 發布 -> 前台驗證」
- 會員可在 2 次點擊內找到新品商品頁

### 6.2 體驗成功指標

- 使用者不再將「建立批次」誤認為「已發布成功」
- 後台可明確知道商品目前屬於 `draft / published / archived` 哪一種狀態
- 會員前台空狀態、已發布狀態與下架狀態皆有明確回饋

### 6.3 驗收型 KPI

- 後台功能名稱完成調整
- 會員前台新增商品展示入口
- 發布與下架操作均能立即反映在會員前台

## 7. 使用者與角色

### 7.1 後台營運人員

特徵：

- 負責商品整理、發布與內容維護
- 關心商品何時對會員可見
- 需要明確的流程與狀態控制

需求：

- 快速建立發布批次
- 確認本次要曝光的商品
- 清楚執行發布與下架
- 可回頭追查某商品由哪一批次發布

### 7.2 會員

特徵：

- 使用會員中心查看最新商品與活動
- 不了解後台批次概念

需求：

- 在固定位置看到最新上架商品
- 看到清楚的商品名稱、圖片、售價與可見狀態

## 8. 使用者場景

### 8.1 後台場景

作為營運人員，我希望先將本週準備推廣的商品整理成一個批次，確認數量與內容無誤後，再正式發布到會員中心，避免商品尚未準備好就提前曝光。

### 8.2 會員場景

作為會員，我希望登入會員中心後，可以從明確的入口看到最新上架的商品，而不是只能看到活動快訊或站內信。

## 9. 當前產品現況

### 9.1 已存在行為

- 後台 `商品近況管理（上架作業）` 可建立批次
- 系統可根據庫存限制上架數量
- 可產生一頁「結果清單」與 CSV 匯出

### 9.2 缺失

- 沒有發布狀態
- 沒有會員展示頁
- 沒有正式發布操作
- 沒有下架機制
- 沒有將「已發布商品」與「所有商品主檔」區分開來

## 10. 產品策略

### 10.1 核心策略

將「上架」拆為兩階段：

1. `建立上架批次`
2. `正式發布到會員前台`

### 10.2 核心原則

- 批次建立不等於前台發布
- 會員前台只能讀取已發布批次中的商品
- 商品可見性由批次狀態決定，而不是由商品主檔單獨決定

## 11. 解決方案總覽

本期將導入兩個產品模組：

### 11.1 模組一：上架批次管理

用於後台建立、查看、發布、下架與封存商品批次。

### 11.2 模組二：會員新品展示

用於會員前台展示所有已發布且符合展示條件的商品。

## 12. 使用者流程

### 12.1 後台流程

1. 進入 `商品管理 > 上架批次管理`
2. 選擇商品與本次發布數量
3. 建立批次
4. 查看批次明細
5. 按下 `發布到會員中心`
6. 系統將批次狀態改為 `published`
7. 後台顯示發布成功訊息

### 12.2 會員流程

1. 會員登入會員中心
2. 進入 `本週新品`
3. 查看已發布商品卡片
4. 點擊商品卡片查看詳情或後續互動功能

## 13. 範圍定義

### 13.1 In Scope

- 功能改名
- 批次狀態欄位
- 批次發布與封存
- 會員前台新品入口
- 會員前台商品列表
- 顯示規則與空狀態設計
- API 與資料模型調整

### 13.2 Out of Scope

- 訂單購買閉環
- 商品評價
- 前台搜尋篩選
- 推播通知自動化
- 活動推薦
- 外部平台同步

## 14. 產品資訊架構

### 14.1 後台資訊架構

- 選單：`商品管理 > 上架批次管理`
- 建議頁面路徑：
  - `/product-status`：第一階段沿用
  - `/product-publishing`：第二階段可考慮調整

### 14.2 會員資訊架構

第一階段建議：

- `會員儀表板 > 本週新品`
- 路徑維持於 `/member/dashboard`

第二階段可升級為：

- 獨立頁面 `/member/products`

## 15. 詳細功能需求

### 15.1 後台功能

#### PBI-01 改名與重新說明

需求：

- 將 `商品近況管理（上架作業）` 更名為 `上架批次管理`
- 補上頁面說明文案

目的：

- 降低誤解
- 讓使用者知道此頁並非直接對會員公開

#### PBI-02 批次建立

需求：

- 使用者可選擇商品與數量建立批次
- 數量不可超過庫存
- 同名商品可先群組選取，再拆回 SKU 明細

輸出：

- 一筆 `ProductListingBatch`
- 多筆 `ProductListingItem`

#### PBI-03 批次狀態

需求：

- 批次需具備以下狀態：
  - `draft`
  - `published`
  - `archived`

規則：

- 新建立的批次預設為 `draft`
- 只有 `published` 會影響會員前台
- `archived` 不得在會員前台顯示

#### PBI-04 批次發布

需求：

- 後台需提供 `發布到會員中心` 操作
- 成功後更新狀態為 `published`
- 記錄 `published_at`

#### PBI-05 批次封存

需求：

- 後台需提供下架或封存操作
- 成功後更新狀態為 `archived`
- 記錄 `archived_at`

#### PBI-06 批次列表

需求：

- 可查看所有批次
- 可依狀態、建立時間、建立人篩選
- 可追查每批次有哪些商品

#### PBI-07 批次匯出

需求：

- 保留現有 CSV 匯出
- 匯出內容作為內部核對用途

### 15.2 會員前台功能

#### PBI-08 新品入口

需求：

- 會員系統需新增一個商品展示入口

建議名稱：

- `本週新品`

#### PBI-09 商品列表展示

需求：

- 以卡片形式顯示商品
- 卡片至少包含：
  - 商品圖片
  - 商品名稱
  - 售價
  - 款式摘要
  - 庫存提示

#### PBI-10 顯示條件

僅顯示符合以下條件的商品：

- 所屬批次為 `published`
- 商品庫存大於 0
- 商品名稱存在
- 商品售價存在

#### PBI-11 排序規則

排序規則如下：

1. 依 `published_at` 新到舊
2. 同批次依 `display_order`
3. 未設定 `display_order` 時依商品名稱

#### PBI-12 空狀態

需求：

- 當沒有可見商品時，顯示清楚的空狀態

建議文案：

> 目前尚無最新上架商品，請稍後再回來看看。

### 15.3 前後台銜接規則

#### PBI-13 建立批次提示

建立批次成功後，系統應提示：

> 本批次已建立，尚未發布到會員中心。

#### PBI-14 發布成功提示

發布成功後，系統應提示：

> 本批次商品已發布到會員中心。

#### PBI-15 前台資料來源限制

會員前台不得直接讀取所有商品主檔，而應只讀取：

- 已發布批次中的商品

## 16. 內容與文案需求

### 16.1 後台頁面標題

- `上架批次管理`

### 16.2 後台頁面說明

建議文案：

> 此功能用於建立本次要發布的商品批次清單。系統會依目前庫存協助整理可發布商品與數量，完成後仍需執行「發布到會員中心」動作，商品才會顯示於會員前台。

### 16.3 會員頁面標題

- `本週新品`

## 17. 資料模型需求

### 17.1 ProductListingBatch

新增或調整欄位：

- `title`
- `description`
- `cover_image`
- `status`
- `published_at`
- `archived_at`

### 17.2 ProductListingItem

新增欄位：

- `display_order`

## 18. API 需求

### 18.1 後台 API

- `POST /product-listings/`
  - 建立批次
- `GET /product-listings/`
  - 查詢批次列表
- `GET /product-listings/{batch_id}`
  - 取得批次明細
- `POST /product-listings/{batch_id}/publish`
  - 發布批次
- `POST /product-listings/{batch_id}/archive`
  - 封存批次

### 18.2 會員 API

- `GET /members/products`
  - 取得會員可見商品列表
- `GET /members/products/{product_id}`
  - 取得商品詳情

## 19. 邊界條件與規則

### 19.1 庫存為 0

- 第一階段不顯示於會員前台

### 19.2 已發布後庫存歸零

- 第一階段直接從會員頁面隱藏
- 第二階段可考慮顯示 `已售完`

### 19.3 同名多款式商品

- 第一階段可顯示群組摘要
- 第二階段再補商品詳情與款式切換

## 20. 風險與依賴

### 20.1 風險

- 若只改名稱，不做會員前台展示，功能價值仍不完整
- 若會員前台直接讀取全部商品，將失去批次發布管理意義
- 若批次狀態設計不完整，前後台會再次脫鉤

### 20.2 依賴

- 後台批次資料模型需先擴充
- 會員頁面需新增入口與 UI
- 會員 API 需先提供正式商品列表資料

## 21. 驗收標準

### 21.1 功能驗收

- 後台已將功能更名為 `上架批次管理`
- 可建立 `draft` 批次
- 可發布批次為 `published`
- 可封存批次為 `archived`
- 會員前台存在 `本週新品` 入口
- 僅 `published` 批次中的商品會顯示

### 21.2 體驗驗收

- 使用者不再混淆「建立批次」與「會員可見」
- 使用者能在固定路徑找到會員新品頁
- 空狀態與發布成功回饋清楚

## 22. 推出策略

### Phase 1

- 改名
- 補說明文案
- 新增批次狀態
- 增加發布與封存操作

### Phase 2

- 新增會員新品展示頁
- 新增會員商品列表 API
- 串接已發布批次資料

### Phase 3

- 新增商品詳情頁
- 新增售完標記
- 新增收藏等互動能力

## 23. 開放問題

- 會員前台第一版要放在 `Dashboard Tab` 還是獨立頁面？
- 第一版是否需要商品詳情頁？
- 是否要在批次發布時允許手動設定封面圖與標題？
- 是否需要同時支援「定時發布」？

## 24. 最終結論

本功能應正式從「內部上架清單工具」升級為「商品發布流程的一環」。

其產品模型應清楚拆分為：

- `上架批次管理`
- `會員新品展示`

只有當後台建立批次、執行發布、會員前台顯示三者形成完整閉環後，「商品上架」這個功能才真正具備清楚的產品意義與商業價值。
