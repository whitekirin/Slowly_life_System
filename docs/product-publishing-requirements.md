# 商品上架批次管理與會員前台展示需求文件

> 狀態：**需求確認中**
>
> 版本：`v1.0`
>
> 文件目的：釐清目前「商品近況管理（上架作業）」的實際用途，重新定義其功能定位，並規劃商品如何正式發布到會員系統中展示。

## 1. 背景與問題說明

目前系統後台存在一個名為「商品近況管理（上架作業）」的功能頁面，操作上可由人員挑選商品、指定數量，建立一筆上架批次資料，並查看結果清單與匯出 CSV。

但依現行系統實作，該功能完成後：

- 不會將商品自動發布到會員系統。
- 不會建立會員可見的商品展示頁。
- 不會在後台商品主檔中留下明確的「已發布 / 未發布」狀態。
- 不會與任何外部商城或公開前台同步。

因此，現況造成以下認知落差：

- 後台使用者容易誤以為「完成上架作業」後，會員端就能看到商品。
- 系統名稱中的「上架」與實際行為不一致。
- 會員系統目前只有 `新品快訊`、`個人資料`、`訂單記錄`、`信件匣`、`紅利商店`，沒有商品展示入口。
- 營運流程缺少「後台建立發布批次」到「會員前台可見商品」之間的正式銜接機制。

本文件目的，即是將這個功能從「內部上架清單工具」正式定義為「發布流程的一部分」，並建立會員端可見的商品展示需求。

## 2. 名詞定義

### 2.1 上架批次

指由後台人員在某一次作業中，挑選本次準備發布的商品及其數量後，所建立的一筆批次資料。

### 2.2 商品發布

指某批商品被正式設定為會員前台可見，並在指定頁面中展示給會員瀏覽的狀態。

### 2.3 會員前台展示

指商品實際出現在會員系統頁面中，可被會員看到、瀏覽與後續互動的狀態。

## 3. 現況分析

### 3.1 目前已存在能力

- 後台可建立商品主檔與多個 SKU / 款式。
- 後台可建立「上架批次」資料。
- 系統可依現有庫存限制上架數量。
- 系統可輸出上架批次明細。

### 3.2 目前缺口

- 沒有批次的發布狀態欄位。
- 沒有會員商品列表 API。
- 沒有會員端商品展示頁。
- 沒有後台「發布到會員前台」操作。
- 沒有商品展示排序與下架規則。
- 沒有明確區分「建立批次」與「實際發布」兩個階段。

## 4. 需求目標

本需求有兩個核心目標：

### 4.1 重新定義現有功能

將現有「商品近況管理（上架作業）」重新命名與重新定位，使其與實際行為一致，避免使用者誤解。

### 4.2 建立會員可見的商品發布流程

讓後台人員在完成批次整理後，能夠將商品正式發布到會員系統，使會員可在明確的頁面中查看商品。

## 5. 功能定位調整

### 5.1 建議新名稱

原名稱：

- `商品近況管理（上架作業）`

建議改名為以下其一：

- `上架批次管理`（建議採用）
- `商品上架準備`
- `上架清單管理`
- `待發布商品整理`

### 5.2 建議功能定義

此功能應被定義為：

> 用於建立本次準備發布到會員前台的商品批次，依庫存整理商品與數量，保留批次紀錄，並支援後續正式發布作業。

### 5.3 建議頁面說明文案

建議顯示於頁面上方的說明文案：

> 此功能用於建立本次要發布的商品批次清單。系統會依目前庫存協助整理可發布商品與數量，完成後仍需執行「發布到會員中心」動作，商品才會顯示於會員前台。

## 6. 使用者角色

### 6.1 後台營運人員

- 建立上架批次
- 檢查商品與數量
- 決定是否發布到會員前台
- 管理批次的上架、下架與封存

### 6.2 會員

- 在會員系統中查看已發布商品
- 瀏覽新品資訊與商品內容

## 7. 系統流程需求

### 7.1 目標流程

正式流程應區分為兩個階段：

1. `建立批次`
2. `正式發布`

### 7.2 建議流程

1. 後台人員進入 `上架批次管理`
2. 選擇本次要發布的商品與數量
3. 系統建立一筆 `上架批次`
4. 後台人員檢查批次內容
5. 後台人員執行 `發布到會員中心`
6. 系統將該批次狀態標記為 `published`
7. 會員前台顯示該批次中的商品
8. 後台可視需要將批次下架或封存

## 8. 功能需求

### 8.1 後台功能需求

#### FR-01 功能名稱調整

- 系統應將原 `商品近況管理（上架作業）` 更名為 `上架批次管理`。

#### FR-02 批次建立

- 後台人員可挑選商品名稱與數量建立一筆上架批次。
- 系統應依商品目前庫存限制可建立的數量。
- 同名商品可先整合顯示，再拆回各 SKU 明細儲存。

#### FR-03 批次狀態管理

- 每一筆上架批次應至少具備以下狀態：
  - `draft`
  - `published`
  - `archived`

建議說明如下：

- `draft`：已建立批次，但尚未對會員可見
- `published`：已正式發布到會員前台
- `archived`：已下架或封存，不再顯示於會員前台

#### FR-04 批次發布

- 後台人員可在批次頁執行 `發布到會員中心` 操作。
- 發布後，該批次中的商品應可在會員前台顯示。

#### FR-05 批次下架

- 後台人員可將已發布批次改為 `archived`。
- 被封存的批次，其商品不應再顯示於會員前台。

#### FR-06 批次資訊欄位

每筆上架批次建議具備以下欄位：

- `id`
- `title`
- `description`
- `cover_image`
- `status`
- `created_at`
- `created_by_id`
- `published_at`
- `archived_at`

#### FR-07 批次明細

每筆批次應記錄以下商品資訊：

- `product_id`
- `quantity`
- `display_order`

#### FR-08 批次查詢

- 後台人員可查看批次列表。
- 批次列表至少應可依狀態、建立時間、建立人員查詢。

#### FR-09 批次匯出

- 系統應保留既有 CSV 匯出能力。
- 匯出的主要用途為內部盤點、人工發布作業或檢核用途。

### 8.2 會員前台功能需求

#### FR-10 會員商品展示入口

- 系統應在會員系統中新增一個商品展示入口。

建議頁面名稱如下：

- `本週新品`（建議採用）
- `新品商品`
- `最新上架`

#### FR-11 會員頁面位置

建議位置有兩種：

- 方案 A：`會員中心 > 本週新品`
- 方案 B：`會員儀表板 Tabs > 本週新品`

第一階段建議採用方案 B，以降低改動成本。

#### FR-12 會員頁面路徑

第一階段建議：

- 若採 Tab 形式：維持在 `/member/dashboard`
- 若採獨立頁面：新增 `/member/products`

#### FR-13 顯示條件

只有符合以下條件的商品，才可於會員前台顯示：

- 所屬批次狀態為 `published`
- 商品當前庫存大於 0
- 商品具有名稱
- 商品具有售價
- 商品具有可用展示圖或預設圖

#### FR-14 展示內容

會員前台商品卡片建議至少顯示：

- 商品圖片
- 商品名稱
- 售價
- 款式或摘要資訊
- 庫存狀態

#### FR-15 商品排序

會員前台顯示順序建議依以下規則：

1. 先依批次 `published_at` 新到舊
2. 同批次內依 `display_order`
3. 若未設定 `display_order`，則依商品名稱排序

#### FR-16 無商品狀態

- 當沒有任何已發布商品時，會員頁面應顯示明確的空狀態文案。

建議文案：

> 目前尚無最新上架商品，請稍後再回來看看。

### 8.3 前後台銜接需求

#### FR-17 建立批次不等於發布成功

- 系統應明確區分：
  - `建立批次`
  - `發布完成`
- 建立批次後，不應直接讓會員可見。

#### FR-18 發布提示

- 當使用者建立批次完成後，系統應提示：
  - `本批次已建立，尚未發布到會員中心。`

#### FR-19 發布結果回饋

- 當使用者成功發布後，系統應提示：
  - `本批次商品已發布到會員中心。`

## 9. 會員前台展示規則

### 9.1 商品顯示來源

會員系統商品資料來源應為：

- `已發布批次中的商品`

而非：

- 所有商品主檔
- 所有有庫存商品
- 所有曾建立過的批次商品

### 9.2 同名商品展示規則

若系統商品主檔內同名商品包含多個 SKU / 款式：

- 前台可依商品群組展示
- 點入後再顯示各款式資訊

若第一階段不做商品詳情頁，則至少需：

- 在列表卡片中顯示名稱
- 補充款式數量或款式摘要

### 9.3 庫存規則

- 若商品已發布，但後續庫存變為 0，建議第一階段直接不顯示。
- 若未來要保留展示，可在第二階段再增加 `已售完` 標籤邏輯。

## 10. 頁面與資訊架構需求

### 10.1 後台頁面

#### 頁面一：上架批次管理

- 位置：`後台 > 商品管理 > 上架批次管理`
- 路徑：`/product-status` 或未來可調整為 `/product-publishing`
- 用途：建立批次、查看明細、執行發布

#### 頁面二：上架批次明細

- 位置：由批次建立後導向
- 路徑：`/product-listing-result/:batchId`
- 建議名稱：`上架批次明細`

### 10.2 會員頁面

#### 頁面三：本週新品

- 位置：`會員中心 > 本週新品`
- 路徑建議：`/member/products`
- 用途：展示所有已發布且符合條件的商品

## 11. API 需求

### 11.1 後台 API

建議新增或調整以下 API：

- `POST /product-listings/`
  - 建立上架批次
- `GET /product-listings/{batch_id}`
  - 查看批次明細
- `GET /product-listings/`
  - 取得批次列表
- `POST /product-listings/{batch_id}/publish`
  - 發布批次
- `POST /product-listings/{batch_id}/archive`
  - 下架 / 封存批次

### 11.2 會員 API

建議新增以下 API：

- `GET /members/products`
  - 取得會員可見商品列表
- `GET /members/products/{product_id}`
  - 取得會員可見商品詳情

## 12. 資料模型需求

### 12.1 ProductListingBatch

建議新增欄位：

- `title: Optional[str]`
- `description: Optional[str]`
- `cover_image: Optional[str]`
- `status: str`
- `published_at: Optional[datetime]`
- `archived_at: Optional[datetime]`

### 12.2 ProductListingItem

建議新增欄位：

- `display_order: Optional[int]`

## 13. 非功能需求

### 13.1 可理解性

- 系統文案需明確區分「建立批次」與「前台可見」兩件事。

### 13.2 可追蹤性

- 應保留批次建立人員、建立時間、發布時間與狀態。

### 13.3 可擴充性

- 後續應能支援：
  - 多批次活動展示
  - 商品詳情頁
  - 收藏功能
  - 售完標記
  - 下架排程

## 14. 驗收標準

### AC-01 名稱一致

- 後台原功能名稱已改為 `上架批次管理`
- 使用者不再誤以為該頁會直接發布到會員前台

### AC-02 流程明確

- 使用者建立批次後，系統會顯示該批次尚未發布的提示

### AC-03 會員入口存在

- 會員系統中可找到 `本週新品` 或等義名稱的商品展示頁

### AC-04 顯示規則正確

- 僅 `published` 批次中的商品會顯示於會員前台

### AC-05 下架生效

- 封存或下架後，該批次商品不再顯示於會員前台

### AC-06 可追查

- 後台可追查某商品是由哪一筆批次發布出去

## 15. 建議分階段實作

### Phase 1：名稱與流程校正

- 將頁面改名為 `上架批次管理`
- 補上批次說明文案
- 補上批次狀態欄位
- 補上 `發布到會員中心` 操作

### Phase 2：會員前台商品列表

- 會員中心新增 `本週新品`
- 新增會員商品列表 API
- 顯示已發布批次中的商品

### Phase 3：商品詳情與互動

- 新增商品詳情頁
- 新增收藏或加入追蹤
- 增加售完展示規則

## 16. 風險與注意事項

- 若第一階段只做頁面改名，但未補會員前台展示，使用者仍可能質疑此功能價值不足。
- 若前台直接讀取所有商品主檔，而不是讀取已發布批次，會破壞「批次發布」的設計目的。
- 若未補批次狀態與發布時間，將無法正確管理前台顯示範圍。

## 17. 最終建議

本功能不應再被定義為「上架成功後即可對會員可見」，而應正式拆分為：

- `上架批次管理`
- `會員新品展示`

後台負責整理、建立與發布批次；會員系統負責展示已發布商品。只有這樣，系統中的「上架」一詞才會具有一致且可驗證的商業意義。
